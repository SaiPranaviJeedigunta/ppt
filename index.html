Performance Problem
The Latency Issues — and How We Fix Them
Two things currently causing lag in the donor experience

❌ The Problems

Voice Interface — 4 to 7 seconds per question Every question requires: speech to text → LLM processing → text to speech. For a 10 question interview that's up to a minute of just waiting. First impressions matter.
Donor speaks
→

LLM (~3s)

Audio back (~2s)
Total per question: 4–7 seconds
Dynamic Questions — LLM called live between every step Generating the next question in real time after every answer adds 2 to 4 seconds of lag between each step. Donors feel the wait.

✓ The Solutions

Voice → Text Interview First (MVP) Build the interview as a smart form for MVP — zero lag, smooth experience. Voice gets layered on top in Phase 2 once the core product is proven. The underlying logic is identical — just a different input method.
Dynamic Questions → Pre-Generated Paths (MVP) Define smart question paths upfront based on cause category. Feels dynamic, zero LLM calls between questions, instant response. Phase 2 adds true streaming adaptability.
Result Donor completes the interview in under 2 minutes with no waiting. Clean, fast, professional first impression.

Pipeline
What the Pipeline Requires
The automated system that transforms raw IRS data into matchable charity profiles
🧹

Data Cleaning

Remove inactive charities with zero revenue. Decode NTEE category codes into plain language. Standardize city, state, and location fields across 400,000 records.

🌐

Website Discovery & Scraping

Find each charity's website. Scrape their About, Programs, and Impact pages. Handle failures gracefully — some sites block scrapers, some have no content, some have no website at all.

🤖

AI Structured Extraction

Send scraped content to an LLM. Extract mission, programs, population served, geography, impact metrics, and philosophical approach as clean structured data.

📦

Embedding & Vector Storage

Convert each enriched charity profile into a numerical vector that captures its meaning. Store in Pinecone so donors can be matched by what they care about — not just keywords.

⏰

Scheduled Automation

The pipeline runs on a weekly schedule using Airflow. Charities update, new ones appear, old ones go inactive. The database stays fresh automatically without manual work.

🎯

Tiered Enrichment Strategy

Start with the top 50,000 most active charities. Enrich the rest over time. Realistically 100,000–150,000 well-enriched profiles — more than enough for excellent matching.

Fields We Extract for Good Matching
Mission StatementWhat the org exists to do — the core purpose in their own words
Programs & ServicesSpecific initiatives — tutoring, food banks, job training, housing etc.
Population ServedWho they help — children, veterans, homeless, refugees, elderly etc.
Geographic ScopeLocal neighborhood, city, state, national, or global reach
Impact MetricsNumbers that show results — people served, outcomes achieved, success rates
Approach & PhilosophyDirect service vs systems change, grassroots vs data-driven, local vs scalable
These six fields combined into one rich paragraph per charity — that's what gets vectorized and matched against donor interests.
Realistic expectation: Not every charity will be perfectly enriched — some have no website, some block scrapers. That's fine. We don't need all 400,000. We need enough high-quality profiles to return matches donors trust.
Backend
What the Backend Requires
The invisible engine that powers every interaction — donors never see this, but everything depends on it
🎤

Interview Service

Takes the donor's form answers and uses an LLM to extract a structured profile — causes, geography, donation size, values, and exclusions. This profile feeds directly into matching.

🧠

Matching Engine

Embeds the donor profile and queries Pinecone with filters — active charities, right geography, right cause. Returns the top 10 charity IDs ranked by how closely they match the donor.

📝

Report Generation Service

For each matched charity, generates a personalized explanation — why this charity fits this specific donor, what they do, their impact, and their EIN. Cached so it's never generated twice.

🗄️

Charity Database API

Clean endpoints to fetch full charity details from PostgreSQL. Handles filtering by active status, geography, and size. Serves data to both matching and the frontend.

🔐

Security & Session Management

API key authentication on all endpoints. Donor session storage so interview answers and match results persist through the experience without requiring user accounts in MVP.

⚡

Performance & Caching

Cache generated reports — same charity never processed twice. Cache embeddings. Target under 3 seconds from interview submission to showing matched results to the donor.

Frontend
What the Frontend Requires
What the donor actually sees — built last, on top of a solid backend
📋

Multi-Step Interview Form

Clean, fast, zero lag. Pre-generated smart question paths that feel dynamic without calling an LLM live. Covers causes, geography, donation size, values, and exclusions.

✨

Results Page

Displays top 10 matched charities ranked by relevance. Clean cards showing charity name, cause, location, and match score. Fast load — results come from cached backend responses.

📄

Charity Report Cards

Each charity gets a personalized explanation — why it matches this donor, what they do, who they serve, their impact highlights, and their EIN for DAF donation instructions.

💳

Donation Info Display

EIN prominently displayed with clear instructions — "Share this with your DAF provider to send your donation." Simple, no payment processing needed in MVP.

📱

Responsive Design

Works on desktop and mobile. Wealthy donors use both. Clean, professional appearance that builds trust — this is handling philanthropic decisions, it needs to feel premium.

🔜

Phase 2 — Voice & Accounts

Voice interview, donor accounts, donation tracking, and dashboards come in Phase 2. The text interview and backend logic is identical — voice is just a different input layer on top.

What gets vectorized: Only fields that describe the charity's domain — mission, programs, population served, impact, approach. Not EINs, revenue figures, or dates.
Fallback strategy: If fewer than 10 results — broaden geography, then broaden cause category, then fall back to pure metadata match. Donor always gets recommendations.
If donor is unsure: Skip semantic search. Return top charities ranked by impact score — Charity Navigator rating, program expense ratio, reach, and data quality. Shown as "Top Impact Charities" not "Your Matches."

Estimated Costs
Cost-efficient by design — validate before spending anything significant

How We Keep Costs Down

🧪

Prove Before Spend

Run the pipeline on 500 charities first. Show real match results. Only scale up after it's validated.

🎯

Right Model for the Right Job

Use cheaper AI models for behind-the-scenes tasks. Reserve the best model only for what donors actually read.

📦

Cache Everything

Once a charity is enriched or a report is generated, we never pay to do it again unless something changes.

🔢

Enrich in Tiers

Start with top 50,000 most active charities. Enrich the rest only when the matching system needs them.
